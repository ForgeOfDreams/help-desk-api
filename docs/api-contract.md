# HTTP API

## Общие правила

API публикуется через API Platform под префиксом `/api`. Документация схемы доступна на
`https://localhost/api/docs` при стандартной локальной конфигурации TLS. Фактический контракт
следует сверять с OpenAPI-документом, сформированным установленной версией приложения.

Защищённые операции используют заголовок `Authorization: Bearer <JWT>`. Запросы на создание и
изменение передают JSON. Для PATCH-операций изменения статуса и назначения тикета используется
`application/merge-patch+json`.

Коллекции поддерживают `page` и `itemsPerPage`; верхний предел `itemsPerPage` — 100. Для тикетов
также предусмотрены фильтры `status` и `priority`.

## Аутентификация и пользователи

| Метод | Маршрут                         | Доступ                       | Назначение                                                   |
| ----- | ------------------------------- | ---------------------------- | ------------------------------------------------------------ |
| POST  | `/api/auth/login`               | Публичный                    | Вход по email и паролю; выдача JWT                           |
| POST  | `/api/auth/register`            | Публичный                    | Регистрация обычного пользователя                            |
| POST  | `/api/auth/verify-email`        | Публичный, одноразовый токен | Подтверждение email                                          |
| POST  | `/api/auth/resend-verification` | Публичный                    | Повторная отправка инструкции без раскрытия наличия аккаунта |
| POST  | `/api/auth/set-password`        | Публичный, одноразовый токен | Завершение приглашения и установка пароля                    |
| GET   | `/api/me`                       | Аутентифицированный          | Данные текущего пользователя                                 |
| POST  | `/api/me/change-password`       | Аутентифицированный          | Смена пароля с проверкой текущего пароля                     |
| POST  | `/api/admin/users`              | `ROLE_ADMIN`                 | Создание/приглашение пользователя или сотрудника поддержки   |

Регистрация возвращает `202 Accepted` с одинаковым нейтральным сообщением независимо от того,
существовал email или нет. Клиент не задаёт роль и состояние активности. Публичная регистрация
создаёт неактивный аккаунт до подтверждения email.

Для `POST /api/admin/users` разрешены `ROLE_USER` и `ROLE_AGENT`. Создание `ROLE_ADMIN` через этот
HTTP endpoint не допускается.

## Тикеты

| Метод | Маршрут                        | Доступ                                           | Назначение                                     |
| ----- | ------------------------------ | ------------------------------------------------ | ---------------------------------------------- |
| GET   | `/api/tickets`                 | Аутентифицированный, результат ограничен правами | Список доступных текущему пользователю тикетов |
| POST  | `/api/tickets`                 | Аутентифицированный                              | Создать тикет от имени текущего пользователя   |
| GET   | `/api/tickets/{id}`            | Владелец/доступный сотрудник/администратор       | Получить доступный тикет                       |
| PATCH | `/api/tickets/{id}/status`     | Агент/администратор                              | Проверить переход и изменить статус            |
| PATCH | `/api/tickets/{id}/assignment` | Агент/администратор                              | Назначить исполнителя и создать запись аудита  |

Вход DTO создания тикета содержит `subject`, `description`, `priority` и необязательный
`categoryId`. Идентификатор автора устанавливается из Security-контекста, а не из пользовательского
JSON.

Изменение статуса принимает `status` и опциональную причину `reason`. Назначение принимает
`assigneeId`. Операции изменения обязаны выполнять серверную проверку доступности тикета и
валидности перехода. Не следует считать успешную сериализацию DTO подтверждением того, что
бизнес-операция разрешена.

## Комментарии

| Метод | Маршрут                            | Доступ                     | Назначение                                                                           |
| ----- | ---------------------------------- | -------------------------- | ------------------------------------------------------------------------------------ |
| GET   | `/api/tickets/{ticketId}/comments` | Доступ к тикету            | Получить доступные комментарии                                                       |
| POST  | `/api/tickets/{ticketId}/comments` | Доступ к тикету            | Добавить публичный комментарий; сотрудник поддержки может создать внутреннюю заметку |
| GET   | `/api/ticket-comments/{id}`        | Доступ к связанному тикету | Получить один комментарий с проверкой видимости                                      |

Входной объект содержит `body` и `visibility`. Значение `internal` не должно разрешаться обычному
пользователю. В API-ответах публичного пользователя внутренние заметки должны быть исключены как при
чтении коллекции, так и при чтении отдельного комментария.

## Категории

| Метод | Маршрут                       | Доступ              | Назначение                             |
| ----- | ----------------------------- | ------------------- | -------------------------------------- |
| GET   | `/api/ticket-categories`      | Аутентифицированный | Список активных категорий с пагинацией |
| GET   | `/api/ticket-categories/{id}` | Аутентифицированный | Получить активную категорию            |

В текущем контракте описано чтение категорий. Отдельный административный CRUD не следует считать
реализованным без соответствующих API Resource и тестов.

## Уведомления

| Метод | Маршрут                        | Доступ                           | Назначение                                                 |
| ----- | ------------------------------ | -------------------------------- | ---------------------------------------------------------- |
| GET   | `/api/notifications`           | Аутентифицированный, только свои | Список уведомлений; `?unread=true` фильтрует непрочитанные |
| GET   | `/api/notifications/{id}`      | Только получатель                | Получить своё уведомление                                  |
| POST  | `/api/notifications/{id}/read` | Только получатель                | Отметить уведомление прочитанным, операция идемпотентна    |

## Примеры запросов

Вход:

```http
POST /api/auth/login
Content-Type: application/json

{"email":"user@example.com","password":"your-password"}
```

Создание тикета:

```http
POST /api/tickets
Authorization: Bearer <JWT>
Content-Type: application/json

{
  "subject": "Cannot access the VPN",
  "description": "The VPN client fails during connection.",
  "priority": "high",
  "categoryId": null
}
```

Изменение статуса:

```http
PATCH /api/tickets/UUID/status
Authorization: Bearer <JWT>
Content-Type: application/merge-patch+json

{"status":"in_progress","reason":"Work started"}
```

Назначение:

```http
PATCH /api/tickets/UUID/assignment
Authorization: Bearer <JWT>
Content-Type: application/merge-patch+json

{"assigneeId":"AGENT-UUID"}
```

## Проверка фактического контракта

Перед выпуском версии экспортируйте OpenAPI либо используйте `/api/docs` и `debug:router`. Важно
проверить, что старый `MeController` не регистрирует дублирующий маршрут `/api/me` после включения
`MeResource`. Должен существовать единственный владелец маршрута.

```bash
docker compose exec -T php php bin/console debug:router
docker compose exec -T php php bin/console debug:config api_platform
docker compose exec -T php php bin/console api:openapi:export --output=/tmp/openapi.json
```

Если установленная версия API Platform не предоставляет `api:openapi:export`, используйте endpoint
документации и `debug:router`.
